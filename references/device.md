# 调试签名、USB 装机与故障分流

## 识别并签名

1. 请用户使用可传数据的 USB 线、解锁手机，按该机界面打开开发者选项和 USB 调试并确认信任。Agent 用 SDK 自带 `hdc list targets -v` 检查。空列表先看数据线/端口/调试开关；Unauthorized 让用户在手机上确认；多设备时先确定实际目标。不要为了连通改用公网调试、重置全部设备或关闭安全校验。
2. 用户要求真机安装时，先比对现有应用包名、目标设备、系统/API、是否覆盖更新。告诉新手覆盖会中断正在运行的会话；确认是否有需要保留的数据。更新沿用与既有安装兼容的签名身份，不用另一应用的包名或证书顶替。
3. 优先沿用本项目已有有效调试签名；缺失时，按当前 DevEco Studio 官方流程尝试自动调试签名。无 IDE 或自动签名不适用时，按官方手动流程准备合法密钥库、调试证书和正确应用的调试 Profile。首次登录/实名/设备信任由用户本人处理；创建账号下的新应用、设备注册或证书/Profile 是额外账号操作，先说明具体变化和范围。不要向用户索取凭证，不自动接受新条款。
4. 签名前核对 Profile 的调试类型、包名、有效期、设备列表与证书是否相符；设备注册标识不等同于 HDC 的 USB 连接键，依据官方流程获取且不要公开。**CER 可能是多张证书的链，不能只拿第一张证书与 Profile 的开发者证书比**。解析并匹配实际签名叶证书，再用官方工具验证输出 HAP。指纹匹配或解析 CMS 不是完整信任验证。
5. 用官方 IDE/CLI 支持的方式传入本地签名材料。不把密钥或密码放在命令行参数、源码、共享文件、录屏或日志；优先使用官方安全存储或交互式输入。若必须临时写工程配置，在无并发修改前提下限制权限，保存原字节和权限，仅在该次构建中使用，异常也恢复并验证；检查缓存/日志，禁止把相关产物与缓存随 Skill、项目 ZIP 或 Git 分享。官方流程不能安全提供凭证时让用户在 IDE 内完成签名，不猜密码、不拆别人的密钥库。

## 验签、安装、启动

- 签完后用当前 SDK 官方验签工具（如 SDK 附带的 `hap-sign-tool.jar verify-app`，参数看该工具帮助）验签。核对包名、版本、内嵌 Profile、目标设备及实际变更资产，记录最终签名包哈希。验签失败或不匹配则不安装。
- 用目标连接键定向执行，下面变量由实际环境提供；不要把真实连接键写入共享文档。首次安装与明确授权的覆盖更新分别按当前 HDC 帮助选择命令；覆盖示例：

```sh
hdc -t "$TARGET" install -r "$SIGNED_HAP"
hdc -t "$TARGET" shell aa start -b "$BUNDLE" -m "$MODULE" -a "$ABILITY"
```

- **仅在安装明确成功后启动**；按模块清单里的主 Ability 替换参数。保存必要、脱敏的证据，检查启动结果/进程与应用相关日志，再验证一项新增功能。不能观察手机界面时请用户点具体入口并反馈，不把进程存在写成 UI 或整局已通过。
- 安装失败按实际报错分流：包未签或签名不匹配 → 对照验签、证书、Profile 和原安装签名；设备不在 Profile 或已过期 → 按授权补正确设备/更新 Profile；系统/ABI 不兼容 → 回到编译配置；版本回退或数据风险 → 停下说明。不尝试卸载、抹数据、换包名或改设备安全设置来跳过错误。

## 上架另立任务

本地调试 HAP 不是发布 APP 包，也不是可任意安装的发行包。用户明确要求商店提交时，按真实应用类别、账号和目标地区，核对当时的华为控制台和官方规则；发布签名、隐私、备案及类别资质单独核对。游戏的离线/免费属性不能用来推断免资质或改报工具。缺必填材料时报告“尚未提交”，不要伪造或报告为“审核驳回”。是否上传、接受条款、提交审核或发布要遵循用户授权及当前工具的确认要求。
