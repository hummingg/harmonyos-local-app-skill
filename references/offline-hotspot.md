# 可选方案：一台鸿蒙手机开房，其他手机用浏览器

适用于用户明确要“只装一份 App、同热点、没有互联网也能用”。以下是可复用设计，不是对所有热点、系统和浏览器的兼容承诺。

## 最小实现

- 房主 App 内运行可关闭/重启的本地 HTTP 服务，并用 ArkWeb 或与需求相符的原生界面参与。网页资源随 HAP 打包，安卓/iPhone/鸿蒙访客浏览器直连；不依赖 CDN、在线字体、云账号或公网域名。为局域网访问选择正确监听接口；如果必须监听所有接口，把服务限制在可信、设密码的私人网络使用，不做公网映射。
- 房主显示可分享的访客 URL 与房间码，二维码不含房主令牌。服务端校验会话、权限、动作与版本，私有数据只发本人；不要把房主凭证放在日志或分享链接。小房间可先用有界、失败退避的 HTTP 轮询，避免未验证就上复杂协议。
- 显示实际可用网卡地址；房主连外部 Wi-Fi 时常有多个接口。若不能可靠识别热点，标出候选并让访客核对 Wi-Fi 网关/实际可达地址，不写死 IP，不选第一块网卡当作事实。访客连同一热点，在系统允许时选择保留无互联网的 Wi-Fi，在浏览器打开完整 `http://<实际热点地址>:<端口>/`。若失败，先确认系统局域网权限、热点设备隔离、端口与房主 App 前台状态，不关闭全局防护。锁屏/后台可能暂停服务，先约定房主保持前台；不默认做后台保活。

## 从本地到四类证据

1. **电脑回归**：实际服务逻辑的隔离浏览器会话完成加入、操作、结算和恢复，禁止外网资源；检查窄屏/横屏。桌面手机视口不是 ArkWeb、Safari 或安卓实机。
2. **真机启动**：验签、定向装机、打开新增入口。不能从安装成功推断热点服务已经开启。
3. **USB 只读冒烟（可选）**：请用户先开房。检查 `hdc fport ls`、选择未占用的本机端口；仅在官方 HDC 已配置为本机回环监听时为目标设备临时建立 `fport tcp:<本机端口> tcp:<手机服务端口>`。建立后核验没有监听外部接口，异常立即撤销。用本机 HTTP 请求检查页面/静态资源与实际构建匹配、未授权接口返回设计的拒绝状态；不冒用房主身份、不占座、不改变牌局。无论成功失败，在清理分支用 `fport rm` 删除自己建立的对应任务，再核对转发列表；不动已有任务。USB 通不代表热点访客通。
4. **热点实机**：按需求让目标系统/浏览器接入同一热点，验证关公网后首次打开、完整对局/业务操作、刷新或断开恢复、再开一局等。按用户反馈和 Agent 实际观察分别写证据；一次成功反馈只确认当次组合，不补填设备数、系统、断公网或重连结论。
